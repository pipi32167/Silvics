# 日记类型 · 低保真原型

对应 [issue #3](https://github.com/pipi32167/Silvics/issues/3)。目的不是"看起来好不好看"，而是把五个判断摆到能点的界面上，先确认方向再写 Swift。

## 怎么看

```bash
cd prototype/journal
python3 -m http.server 8791
# 打开 http://127.0.0.1:8791/index.html
```

- 纯静态，零依赖，零构建。
- 数据是种子数据，点击结果存 `localStorage`，刷新不丢；右上角「重置」回到初始状态。
- **「今天」固定为 2026-11-24**，否则种子里的日记日期会漂。
- 快捷键：`⌘⇧J` 跳到今天、`⌘⇧T` 待办总览、`⌘P` 按标题打开（浏览器可能抢 `⌘⇧J`，面板里都有按钮）。

## 已定的五个决定（对应界面位置）

| 决定 | 在原型里看哪里 |
| --- | --- |
| 承接来自「上一个有日记的日子」 | 新建弹窗里的「承接预览」写明来源日期；种子里 11-22 没有日记，所以 11-24 承接的是 11-23 |
| 承接段要标来源 | 日记正文里的 `承接（来自 11-23）` |
| 日记的 `[[ ]]` 计入连接图 | 在日记里写 `[[稀疏重复优于集中突击]]`，再看这条概念笔记的反向链接，会多出「2026-11-24 日记」 |
| 日记不参与提及扫描，给开关 | 右栏「未链接提及 → 日记参与提及扫描」 |
| 模板是模块段落 | 新建弹窗里勾「工作 / 生活 / 锻炼」，按 order 依次拼成段落 |

## 哪些是假的

- Markdown 渲染：只把 `[[ ]]` 变成可点的蓝字，其余原样。
- `[[` 补全、撤销栈、自动保存：不做。
- git 同步、vault 写入：不做。日记沿用现有 vault 与同步机制，原型不模拟。
- 日历、提醒、周报、移动端：不做。

## 走查中暴露的三个问题（想请你定）

1. **承接是跨模块的。** 今天承接来的「补 issue 里五个待定项」原本属于 11-23 的「工作」段，现在混进了「承接」段。要不要改成「只承接指定模块」（例如只承接「工作」）？
2. **待办总览的日期标签会误导。** 条目写「最近出现在 11-24 · 共 3 天」，但 11-24 那次是承接过来的副本，不是原创。要不要改成显示「最早出现 11-21」？
3. **日记引用概念会影响「被引用 N」计数。** 概念笔记侧栏显示的被引用数把日记也算进去了。要合并计数，还是分开显示「笔记 2 · 日记 1」？
