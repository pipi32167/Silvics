# 导航互动原型

对应 [issue #32](https://github.com/pipi32167/Silvics/issues/32)。

回答两个问题：

1. 三个模块各有一个入口，还是共用一个侧栏？（看观感）
2. 切走再切回，要不要回到原处？（看状态）

## 怎么看

```bash
cd prototype/nav
python3 -m http.server 8792
# 打开 http://127.0.0.1:8792/index.html
```

零依赖、零构建。也可以直接双击 `index.html`。

- 底部浮条切四种骨架，直链 `?variant=a|b|c|d`。
- 右下角状态面板显示模块、范围、选中、查询。
- 数据是假的，状态只在内存里，刷新即还原。右上角「重置」回到初始状态。

## 四种骨架

| 变体 | 切换位置 | 侧栏职责 | 看什么 |
| --- | --- | --- | --- |
| A 工具栏分段 | 工具栏中央 | 范围 + 列表 | 切换是否够快；工具栏是否被占 |
| B 侧栏四行 | 侧栏顶部 | 模块 + 范围 + 列表 | 模块行会不会和列表行混在一起 |
| C 侧栏内分段 | 侧栏顶部 | 分段 + 范围 + 列表 | 分段缩在 244 px 里是否还认得出 |
| D 四栏 | 侧栏顶部 | 只放导航，列表独立成栏 | 四栏横向空间是否够；列表与内容切换是否顺 |

判据：不看「好不好看」，只回答三个问题。

- 切模块要几次点击、鼠标移动距离多少？
- 切过去以后，知不知道自己在哪个模块？
- 换成 700 px 窄窗口，这个骨架还能用吗？

## 两个开关

| 开关 | 验证什么 |
| --- | --- |
| 记住状态 | 打开：切走再切回，选中条目与范围保留。关掉：目标模块重置成默认范围与第一条。 |
| 窄窗口 | 宽度压到 700 px，右栏隐藏；方案 A 的工具栏分段退成下拉菜单。 |

## 快捷键

| 键 | 行为 |
| --- | --- |
| `⌘1` / `⌘2` / `⌘3` | 切到笔记 / 日记 / 剪藏 |
| `↑` / `↓` | 在当前列表里移动选中 |

## 已知边界

这个原型只回答导航问题，以下都不做：

- 没有真实抓取、没有模型调用、没有同步。
- 正文不能编辑。「编辑正文」按钮只是占位，用来看剪藏只读态的位置。
- 设置窗口不画。方案 B 与 D 的「设置」行是灰的，只演示入口位置。
- 不做窄窗口以外的响应式断点。

## 与 `prototype/journal/` 的关系

色板与排版沿用 `prototype/journal/style.css`：灰线、黑字、一个强调色。这里不模拟 macOS 观感，免得评审去比「好不好看」。那个原型验证编辑器手感，这个验证导航骨架。两者互不依赖。

## 定稿后

选定哪个骨架，把结论写进 issue #32，再按 issue 里的批次改成 SwiftUI。原型本身留在 `feat/nav-prototype` 分支，不进 main。
