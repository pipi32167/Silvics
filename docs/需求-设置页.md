# 需求：设置页面

对应 issue [#2](https://github.com/pipi32167/Silvics/issues/2)。状态：已实现（PR #7），待合并。

已定：字体族三档；设置存本机 UserDefaults（不跟 vault）；导出配置不含密钥；L4 换 embedding 模型时旧向量作废（L4 本体未做，实现时按此执行）。
前置阅读：`docs/设计文档.md` 8.6（BYOK 预设表）、11.2（主题）、`docs/HANDOFF.md` 第 9 节（P4）。

---

## 1. 问题

应用没有设置入口。两类配置无处可放：

1. **外观**：正文字号、代码字号、行距、字体族写死在 `EditorKit/Theme.swift`，用户改不了。
2. **模型服务**：L3（概念线索）与 L4（相关笔记）需要用户自带 key，现在没有录入、校验、存储的地方。

后果：L4 永远做不了；不同屏幕与视力的人用同一个字号。

## 2. 范围

| 做 | 不做 |
| --- | --- |
| 独立设置窗口（`⌘,`） | 自定义配色方案（设计文档 11.2 排到 P6 之后） |
| 外观：字号、行距、字体族 | 界面缩放（整窗 zoom） |
| BYOK：预设服务商、自定义、密钥、测试连接 | 订阅制 / 内置额度 |
| 配置读写、迁移、重置 | 多用户 / 多套配置切换 |
| 未配置时的降级提示 | 模型参数细调（temperature、max_tokens） |

## 3. 场景

1. 新装应用，打开设置 → 选服务商 → 粘 key → 测试连接 → 通过 → 关闭。L3/L4 从灰色变可用。
2. 用外部显示器时把正文字号从 15 调到 17，编辑区立即变化，不用重启。
3. 换机器：导入配置（不含 key）→ 重新填一次 key。笔记与配置分开管理。

## 4. 入口与结构

- 入口：菜单「Silvics → 设置…」，快捷键 `⌘,`（SwiftUI `Settings` scene，系统自带窗口行为）。
- 三个标签页：

```text
设置
├─ 外观      字号、行距、字体族、实时预览、恢复默认
├─ 模型服务   服务商列表、编辑表单、用途绑定、测试连接
└─ 关于      版本、构建号、数据目录、链接到仓库与发布页
```

- 设置窗口宽 620、高 460，可缩放；标签页内容独立滚动。

## 5. 外观

### 5.1 可配项

| 项 | 取值 | 默认 | 生效范围 |
| --- | --- | --- | --- |
| 正文字号 | 13–19，步长 1 | 15 | 编辑区正文、补全浮层条目 |
| 代码字号 | 11–16，步长 0.5 | 13.5 | 行内代码、代码块 |
| 行距 | 3–9，步长 1 | 5 | 编辑区段落 |
| 字体族 | 系统无衬线 / 系统衬线 / 等宽 | 系统无衬线 | 正文；标题跟随同族，字重不变 |

标题字号按正文比例缩放：正文 15 时一级标题 26（约 1.73 倍）。改正文后各级标题按原比例重算，不另设控件。

### 5.2 交互

- 全部即时生效：拖动或改值 → `AppState` 发布 → 编辑区全量 restyle（已有 0.25 ms 解析预算，够用）。
- 窗口底部常驻「恢复默认」；仅恢复外观，不动模型服务。
- 无「保存」按钮。改动即保存，符合系统偏好设置习惯。

### 5.3 实现要点

- `Theme` 现在全是 `static let`，改成由 `ThemeSettings` 驱动：保留语义色不变，只让字体与段落样式从设置取值。
- 新增 `Core/AppearanceSettings.swift`（`Codable` + `Equatable`，UserDefaults key `silvics.appearance.settings`），写法照 `SyncSettings`。
- `NoteEditorView` 增加 `appearance` 参数；值变化时走 `restyle(force: true)`。
- 样式不写进正文。`note.body` 里不出现字号、字体信息，换机器靠设置恢复。

## 6. 模型服务（BYOK）

### 6.1 数据模型

```swift
enum ProviderKind: String, Codable { case openAICompatible, anthropic, gemini }
enum Capability: String, Codable { case chat, embedding, both }

struct ProviderConfig: Codable, Identifiable, Equatable {
    var id: UUID
    var name: String              // 展示名，可改
    var kind: ProviderKind
    var baseURL: URL
    var chatModel: String         // 空串表示不提供 chat
    var embeddingModel: String    // 空串表示不提供 embedding
    var keyAccount: String        // Keychain account，默认 "provider-<uuid>"
    var enabled: Bool
}

struct ProviderSettings: Codable, Equatable {
    var schemaVersion: Int = 1
    var providers: [ProviderConfig] = []
    var chatProviderId: UUID?      // L3 用哪个
    var embeddingProviderId: UUID? // L4 用哪个
}
```

规则：

- 一个 provider 可同时提供 chat 与 embedding（`both`）；模型名分开填，空串即不提供。
- 预设只填 `baseURL`、`kind`、默认模型名。用户只补 key。
- 自定义 provider 全部字段手填。
- 同一个 provider 不能重复添加（`kind + baseURL` 归一化后判重）。

### 6.2 预设

照设计文档 8.6：OpenAI、Anthropic、DeepSeek、Moonshot、阿里百炼、智谱、硅基流动、OpenRouter、Jina、Voyage、Ollama（`http://127.0.0.1:11434/v1`）、自定义。

预设是**代码里的只读表**，不写进设置 JSON。用户改动预设即生成一个新的自定义 provider，不污染预设。

### 6.3 密钥

| 项 | 约定 |
| --- | --- |
| 存储 | Keychain（`kSecClassGenericPassword`） |
| service | `com.silvics.app.provider` |
| account | `provider-<uuid>` |
| 数据库 / UserDefaults | 只存 `keyAccount`，绝不存明文 |
| 界面 | 只显示后 4 位（`sk-…a1b2`）；不提供「显示明文」 |
| 日志 | 请求头一律脱敏；`DebugLog` 不得写入 key |
| 导出配置 | 不含 key（导出的是 `ProviderSettings`，本来就没有 key 字段） |

测试需要注入：定义 `protocol SecretStore { read/write/delete }`，生产实现用 Keychain，单测用内存实现，避免测试依赖系统钥匙串。

### 6.4 用途绑定

- 「概念线索（L3）」选一个 chat provider；「相关笔记（L4）」选一个 embedding provider。
- 未绑定或 key 缺失：L4 面板灰显并提示「未配置 embedding 服务」，L3 退回纯本地分词（`NLTokenizer`，设计文档 3.4）。
- 删除 provider 时一并清 Keychain、清绑定，并提示哪两个功能受影响。

### 6.5 测试连接

| 项 | 规则 |
| --- | --- |
| chat | `POST /chat/completions`，messages 一条 `ping`，`max_tokens=1` |
| embedding | `POST /embeddings`，input 一个短句，取向量长度 |
| 超时 | 10 秒；超时文案「连接超时，检查 baseURL 或网络」 |
| 成功 | 显示耗时与返回模型名 |
| 失败 | 显示 HTTP 状态码与响应里的 `error.message`（截断 200 字），映射 401 / 403 / 404 / 429 / 5xx 到中文说明 |
| 并发 | 同一 provider 测试中禁用按钮，避免并发请求 |

## 7. 存储、迁移、重置

| 项 | 决定 |
| --- | --- |
| 外观 | UserDefaults `silvics.appearance.settings`（JSON） |
| 模型服务 | UserDefaults `silvics.providers.settings`（JSON），key 在 Keychain |
| 为什么不进数据库 | 与 `SyncSettings` 一致。设置属于本机，不参与笔记备份与 git 同步 |
| 迁移 | 两个结构都带 `schemaVersion`；解码失败回默认并在状态条提示，不让应用起不来 |
| 重置 | 「关于」页提供「恢复全部设置」：清两个 UserDefaults key + 删全部 provider 的 Keychain 项，二次确认 |

## 8. 验收标准

外观：

1. 正文设为 13 / 15 / 19 后，读 `NSTextView.font.pointSize` 分别为 13 / 15 / 19。
2. 行距设为 3 与 9 时，段落样式 `lineSpacing` 分别为 3 与 9。
3. 字体族切到「等宽」后，正文字体 `fontDescriptor.symbolicTraits` 含 `.monoSpace`。
4. 改完重启应用，四项设置仍在。
5. 清空 `silvics.appearance.settings` 后回默认 15 / 13.5 / 5 / 系统无衬线。
6. 切换外观不修改任何笔记正文（对比切换前后 `note.body` 与 `body_hash`）。

模型服务：

7. 从预设选 OpenAI，只填 key 即可保存；`baseURL` 与模型名自动带出。
8. 保存后 Keychain 存在该 account；导出 JSON（打印 `ProviderSettings`）不含 key 明文。
9. 错误 key 测试连接返回 401，界面显示中文说明与状态码。
10. 正确 key 测试连接 < 5 秒内返回，显示耗时与模型名。
11. 未绑定 embedding 时，L4 区域灰显且点击给出提示；L3 仍可用。
12. 删除 provider 后 Keychain 项消失，绑定被清空。
13. 重复添加同一 provider 被拒绝并提示。
14. 自定义 provider 的 `baseURL` 非 http(s) 时拒绝保存。
15. 「恢复全部设置」后：UserDefaults 两个 key 清空、Keychain 全部删除、界面回到默认。

通用：

16. 设置窗口 `⌘,` 可开，Esc 不关闭（系统偏好行为），`⌘W` 关闭。
17. 全部控件可 Tab 到达，VoiceOver 能读出标签与当前值。

## 10. 风险

| 风险 | 对策 |
| --- | --- |
| Keychain 在测试环境不稳定 | 单测注入内存 `SecretStore`，只在真机手测 Keychain |
| 改字体导致中文行高错位 | 字号与字体族只改 `NSFont`，不动布局；改完用 `DebugCapture` 取 4 组对照图 |
| 用户把「自定义」当预设改 | 编辑器改动预设即另存为自定义，不覆盖预设 |
| 设置丢失（UserDefaults 被清） | 解码失败回默认并提示；不阻塞启动 |
| 换机器后模型配置丢失 | 「导出配置」不含 key，配合笔记 vault 同步手动搬 |
