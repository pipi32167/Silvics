# 日记编辑器边界用例

给「日记 = 一份 Markdown 文本，光标行露源码、其他行渲染」这套编辑器用的用例库。
**编号是契约**：原型里能一键跑，Swift 实现时按同一批编号写 XCTest，验收不重新发明标准。

- 原型：`prototype/journal/`
- 自动化用例：`prototype/journal/edgecases.js`，面板按钮「边界用例」
- 现状：77 条页内用例 + 28 条端到端交互审计全部通过，9 条需人工在真机确认

## 0. 前提约定

| 约定 | 说明 |
| --- | --- |
| 文本是唯一真相 | 编辑结果永远落回 `body: string`；DOM / 视图只是投影 |
| 行级渲染 | 一行一个块，行内语法（`**`、`[[ ]]`、`` ` ``）在块内渲染 |
| 只有当前行可编辑 | 光标所在行显示原始文本，其余行不可编辑；点击切行 |
| 勾选即改文本 | 复选框点击 = 改那一行的 `[ ]` ↔ `[x]`，不新增状态 |
| 不做嵌套 | 缩进保留，但不做嵌套列表语义 |

## 1.4 列表 / 待办 / 引用（S28–S54）

标记渲染的总规则：**非光标段落把标记压宽到 ≈ 0**（字号 0.1 pt + 负 kern），
正文从 `ListLayout.offset(level:)` 处开始，项目符号 / 序号 / 复选框由视图自绘；
**光标段落恢复原宽、不画浮层**，按「露源码」处理。正文一个字符不动。

左缘规则（issue #50 起，替换第 1 版的固定 22 pt）：

- 第 1 级列表、待办、引用的**正文与标题、正文同左缘**（offset = 0）。
- 项目符号（正文左 10 pt）、复选框（正文左 20 pt）、引用竖线（正文左 9 pt）挂在左边留白里，不占正文位置。
- 每深一级（2 个空格或 1 个 tab）右移 18 pt，符号换形状：`•` → `◦` → `▪`。最深按第 3 级排。

**行首缩进是例外：它在任何状态下都不占宽**（S49–S53，issue #41）。
光标段落只露出语法标记本身（`- `、`1. `、`- [ ] `、`> `、`## `），
不露缩进 —— 否则 `  - 甲` 一进编辑态正文就右移 8 pt，光标移开又缩回去。

### 4.1 组字期间的渲染（R01–R08，issue #49）

输入法组字期间 `restyle` / `refreshSyntaxMarksForCaret` 一律让路（I01–I04），
于是「按字符偏移画出来的东西」会停在组字前的偏移上。

| 编号 | 场景 | 期望 | 现状 |
| --- | --- | --- | --- |
| R01 | 组字把下面的行往下挤 | 其余行的复选框留在自己那一行，勾选态不串 | 通过 |
| R02 | 组字期间重复布局 | 复选框位置与状态不变（幂等） | 通过 |
| R03 | 上屏之后 | 回到渲染态，浮层与正文对齐 | 通过 |
| R04 | 组字期间已有正文 | 属性摘要（字号 / kern / 字色）一个字节都不变 | 通过 |
| R05 | 组件矩阵：标题 / 列表 / 待办 / 引用 / 表格 / 代码块 / 行内代码 / 粗斜体 / 引用链接 / 分隔线 | 组字期间渲染不变，上屏后正文正确 | 通过 |
| R06 | 光标段落 | 露源码、不画复选框（承 S40），其余行浮层不动 | 通过 |
| R07 | 组字串长到换行 | 浮层跟着下移，不停在原位 | 通过 |
| R08 | 引用竖线 / 代码块底色区间 | 组字期间与当前正文一致，不画到别的段落 | 通过 |

浮层的硬前提：`listMarkers` 必须是从当前正文解析出来的（`setListMarkers(_:parsedFrom:)`）。
偏移对不上就整批不排，宁可停着也不能按过期偏移摆。

项目符号不用 `NSTextList`：本机实测 TextKit 2 下它只把正文推到固定 36 pt 处、**不画标记**，
且忽略 `firstLineHeadIndent`（设 22 与设 8 结果相同），无法与 kern 压宽配合。
改用「固定缩进 + 自绘符号」，实测软换行对齐差 ≤ 0.02 pt。

待办不用 `NSTextAttachment`：附件会改写正文（197 → 177 字）。改用段落左侧的 `NSButton` 浮层，
按钮中线与文本中线偏差 0 pt，滚动时跟着走。

行首缩进压宽有个例外：**tab 走制表位，字号与 kern 都压不住它**。
`NSParagraphStyle.defaultTabInterval` 默认 28 pt，行首那个 tab 会白占 6 pt（缩进 22 → 下一个格 28）。
列表 / 引用段落因此清空 `tabStops`、把 `defaultTabInterval` 压到 0.1 pt（S51）。
不能写 0：实测间隔为 0 时 TextKit 2 不再给这一段产出 `textLineFragments`，整段量不到位置。

## 1.5 代码高亮（H）

高亮只改属性、不改文本，所以有一条最强的约束：**所有 token 拼回去必须等于原文**（H01）。

| 编号 | 场景 | 期望 | 现状 |

| H02 | 字符串里的 `//` | 不算注释 | 通过 |
| H03 | 注释里的引号 | 不开启字符串 | 通过 |
| H04 | 未闭合块注释 | 吃到块尾，不泄漏到下一块 | 通过 |
| H05 | Python 三引号跨行 | 仍是一个字符串 token | 通过 |
| H06 | JS 模板字符串 | 整体当字符串（内部不细分，已知取舍） | 通过 |
| H07 | JSON 里的 `//` | 不是注释 | 通过 |

| H09 | 未知语言 | 退到通用词法，不抛错 | 通过 |
| H10 | 语言标记归一 | 大小写、`ts`→js、`sh`→bash、`math`→latex、未知→generic | 通过 |

支持的语言：`swift` / `js`(含 ts) / `python` / `json` / `bash`，无标记或未知标记走通用词法（字符串、数字、注释）。

## 1.6 公式块（L）

**公式当块级代码处理**：写 ```` ```latex ```` （别名 `math` / `tex` / `katex`），不引入 `$…$` 行内语法。

| 编号 | 场景 | 期望 | 现状 |
| --- | --- | --- | --- |
| L01 | `\frac`、`\alpha` | 按命令着色 | 通过 |
| L02 | `%` | 是注释 | 通过 |
| L03 | ` ```latex ` 块 | 识别为代码块，语言记为 latex | 通过 |

为什么不用 `$…$`：省掉全部定界符歧义（`$100 和 $200`、`\$` 转义、代码里的 `$`），也不用往正文里塞附件。
代价是**不支持行内公式**，v1 接受。

- 解析用 `swift-markdown` 的 AST，写入是纯文本按行插入，**不重新序列化整篇**。

- 归属看标题路径（`## 工作` 下的 `### 部署` 归 `["工作","部署"]`），不只看最后一级标题。
- 判重是整篇按去首尾空白的文本比对，不看勾选状态。
- 嵌在已勾父条目下的未完成项会被提升成同级，搬的时候去掉整块共有缩进（`JournalMerge.dedent`）。
- 界面上「融合」按钮（编辑区标题栏，日记才出现）与 `⌘⇧J` 新建走同一条 `JournalMerge.merge`，
  不存在第二份实现。

## 6.1 行内区间与块引用续行

cmark 给行内节点报的 `column` 在块引用的**懒惰续行**上会多算 `> ` 的宽度
（`> 甲` 换行后直接写正文、不再写 `>`）。整行右移会让 `**粗**` 的区间取成 `粗**`：
星号露在屏幕上，粗体也错位。`MarkdownStyler.columnShifts` 用行内 `Text` 节点的原文
在原始行里找回真实位置，按行修正；**只修块内行内节点**，块级节点的 column 本来就是原始列。

## 8. 已知取舍（别当 bug 修）

0. **只有当前行可编辑，方向键必须手工接管**。浏览器不会把光标移出 `contenteditable` 块，
   所以 `↑↓←→` 在行边界要自己改激活行并恢复列位置。这是原型里被用户报出来的第一个可用性 bug，
   实现时 `NSTextView` 不需要这段逻辑（它本来就是整篇一个文本视图）。
1. **跨行选区不支持**。原型里只有当前行是 `contenteditable`，跨行选不成立。Swift 端用 `NSTextView` 没有这个限制，但**样式重算要按可见段落做**，否则整篇重排会卡。
2. **撤销不保证**。原型每次换行都重绘 DOM，与浏览器原生 undo 冲突。实现里必须走 `NSUndoManager`，一次换行 = 一个 `replaceCharacters` 操作。
3. **合并可能产生畸形 Markdown**。在 `- [ ] a` 行首退格与上一行标题合并，会得到 `## 承接（来自 11-21）- [ ] a`。这是文本编辑器的正常行为，不做修复，也不做提示。
4. **点击行中间落点**。原型落行尾；实现用 TextKit 的 `characterIndex(for:)` 拿到真实落点。
5. **公式只高亮、不排版**。`latex` 块现在是普通代码块 + 命令着色，没有数学排版。真要排版，最省事的落点是只读视图与导出（块级渲染，不涉及行内附件与光标）。
6. **代码高亮不做嵌套语法**：模板字符串里的 `${}`、Python 的 f-string 内部表达式都整体当字符串。够用，不追求精确。
7. **代码块围栏标记仍然可见**（淡化到 45% 透明度）。Typora 是隐藏围栏、点空白进入块内编辑；我们只有当前行可编辑，隐藏后围栏行不好点，所以先保留。要实现隐藏，得先解决「点击代码块空白处激活块编辑」。
8. **四个及以上反引号不做嵌套围栏**，一律按三个处理。日记里贴 MD 语法示例时要注意。
9. **没有嵌套列表**。缩进只保留，不改语义；需要嵌套时在实现里单独定，别偷偷加。

## 9. 移植到 Swift 的对照

| 原型里的东西 | NSTextView / TextKit 2 对应做法 |
| --- | --- |
| `describeLines(body)` | 按 `NSString.paragraphRange` 遍历，用 `NSRegularExpression` 分类；结果缓存到 `NSTextStorage` 的属性里 |
| `inlineHTML(text)` | 直接对 `NSTextStorage` 加属性：`foregroundColor`（链接）、`font`（粗斜）、`backgroundColor`（行内代码） |
| 「当前行露源码」 | 光标所在段落把语法前缀（`## `、`- [ ] `、`[[`、`]]`）的字色从 `.clear` 改回正常色。**这就是设计文档里被搁置的「方案 B」** |
| `todo-box` 点击 | `NSTextAttachment`（勾选框图）+ `characterIndex` 命中测试；勾选 = `replaceCharacters(in: 那一行, with:)` |
| `Model.splitLine` / `mergeBackward` | `textStorage.replaceCharacters(in:range:with:)`，一次操作一个 undo 分组 |
| `composing` 标志 | `hasMarkedText()`。组合期禁止改属性、禁止重绘，否则会吞字 |
| `insertCarry` | 以 `selection` 所在段落的 `paragraphRange.location` 为插入点，插完把光标放到块尾 |
| `plainTextOf` | 导出给反向链接/提及扫描前，剔除代码块与行内代码的字符区间 |
| 围栏配对 | 按 `^\s*``` ` 逐行翻转 `inFence`；实现里用段落扫描一次算完并缓存，不要每帧重算 |
| 「浏览器塞进来的 `<div>`」 | 原型用 `innerText` + 按行拆分兜底。`NSTextView` 不会发生，但**粘贴 HTML 会**，仍要走「只取纯文本」 |

## 10. 怎么用这份清单

1. **写实现前**：先按编号补 XCTest 用例名（`testS06TodoNeedsSpaceAfterBracket` 之类），红着开工。
2. **做评审**：不接受「看起来对」。每条编号要么有自动化用例，要么在真机截图里能指出来。
3. **加新用例**：编号只追加不重排。弃用的标「作废」，不要复用编号。
4. **原型验证过的行为就是基线**。实现与原型不一致时，先确认是有意改进，再改编号对应的期望。
