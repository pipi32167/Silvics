# 日记待办融合（issue #48）

把「承接段」换成「按模块融合」。上一篇日记的未完成待办，按标题路径并进当天同名段。

## 1. 目标形态

新建 11-27 日记时（模板骨架 = 工作 / 生活）：

```markdown
## 工作
- [ ] 迁移 gitlab runner & pg 到上海机器上

## 生活
- [ ] 拿口罩
- [ ] 买咖啡豆
```

改前是这样（所有模块的条目混在顶部）：

```markdown
## 承接（来自 11-26）
- [ ] 迁移 gitlab runner & pg 到上海机器上
- [ ] 拿口罩
- [ ] 买咖啡豆

## 工作

## 生活
```

## 2. 方案：树定位 + 文本插入

- 解析用 `swift-markdown`（已是依赖，`MarkdownStyler` 已在用 `SourceRange`）。
  它默认挂 cmark-gfm 的 `tasklist` 扩展，`ListItem.checkbox` 直接读勾选状态。
- 树只用来**定位**：算目标节点、段边界、插入行号。
- 写入是**纯文本按行插入**，一个字节都不重排。
  禁止用 AST 重新序列化整篇：表格对齐、行内样式、围栏信息、git diff 全会被重写。
- 树不落盘。一旦树成为存储真相，就要和混合模式编辑器（光标段落露源码）、
  `UndoManager`、外部改写计数做双向同步，成本远超收益。

## 3. 规则

| 项 | 规则 |
| --- | --- |
| 来源 | 上一个有日记的日子，一跳；中间漏写不补 |
| 归属 | 待办归它前面最近的标题路径（`["工作","部署"]`），不是只看最后一级 |
| 落点 | 当天同名段的最后一个非空行之后；段内全空就紧跟标题行 |
| 顺序 | 按来源出现顺序追加，不排序、不改写文本 |
| 判重 | 整篇按去首尾空白的文本比对；出现过就跳过，不看勾选状态 |
| 缺段 | 全路径不中 → 末级标题唯一命中兜底 → 都不中按来源层级补标题链 |
| 段外 | 第一个标题之前的待办 → 当天第一个标题所在段；一个标题都没有 → 正文末尾 |
| 代码块 | 围栏里的 `- [ ]` 不算待办（AST 天然排除） |
| 嵌套 | 带子块的待办整块搬；父项已勾的子项提升成同级并去掉共有缩进 |
| 幂等 | 同一天重复触发不重复追加 |
| 来源记录 | frontmatter `journal.carryFrom` 继续写来源日，右栏显示「融合自」 |
| 可见标记 | 不加。条目文本与来源一字不差 |

## 4. 实现

### 4.1 新增 `Sources/Silvics/Core/JournalMerge.swift`

```swift
enum JournalMerge {
    struct Carried: Equatable { var path: [String]; var level: Int; var text: String; var lines: [String] }
    struct Placement: Equatable { var section: String; var count: Int }
    struct Merge: Equatable { var body: String; var added: Int; var skipped: Int
                              var placements: [Placement]; var statusText: String }

    static func openTodos(in body: String) -> [Carried]
    static func todoTexts(in body: String) -> Set<String>
    static func merge(into body: String, from items: [Carried]) -> Merge
    static func headings(in body: String) -> [HeadingRecord]
    static func todoNodes(in body: String) -> [TodoNode]
    static func todoText(fromLine line: String) -> String?
    static func dedent(_ lines: [String]) -> [String]
}
```

内部 `SectionIndex` 按标题建索引：`path → (level, line, endLine, insertAfter)`。
每插一条重建一次索引——行号与段边界都会变，重算比分片维护偏移更不容易错；
日记几 KB、条目几十条，代价可以忽略。

### 4.2 `JournalCarry.swift` → `JournalCaret.swift`

删 `heading` / `insert` / `insertion` / `hasCarry` / `openTodos`。
只留 `lineIndex(ofUTF16Offset:in:)` / `utf16Offset(ofLine:in:)`（右栏跳转还在用）。

### 4.3 新建链路 `NoteStoreJournal.journalNote(on:using:)`

```swift
if let previous = try previousJournal(before: day), let previousDay = previous.metaFields["date"] {
    let items = JournalMerge.openTodos(in: previous.body)
    let merged = JournalMerge.merge(into: body, from: items)
    if merged.added > 0 { body = merged.body; meta["carryFrom"] = previousDay }
}
```

### 4.4 手动触发 `AppState.mergePreviousTodos()`

去掉光标行计算与 `placeCaret`。提示语来自 `Merge.statusText`（`融合 2 条：生活 1、工作 1。`），
全部已存在时给 `11-26 的未完成项已经在正文里了。`

界面：「融合」按钮（`RootView`，`journal-merge`）、菜单「融合上次未完成（按模块）」、
右栏「融合自」。

### 4.5 演示与演练

`DemoSeeder` 直接写融合后的正文；`JournalDrill` 断言「工作段有、生活段有、正文无承接、已完成不搬」；
`DebugCapture` 的 `SILVICS_JOURNAL_CARRY` → `SILVICS_JOURNAL_MERGE=1`。

## 7. 遗留

- 旧日记里的承接段不自动整理（默认不动历史）。要整理就另开一个「把承接段拆回各段」的动作。
- 截图取证要用 `SILVICS_DB` + 先把默认 vault 指到沙箱目录，否则启动自愈会把真实库内容写进沙箱。
