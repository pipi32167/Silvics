# 表格渲染（等宽 + kern 补齐）

本文按「简化技术中文」原则写作：短句、一句一个动作、主动语态。

## 1. 结论

表格识别与渲染已实现，正文一个字符都不改。

- 整块用等宽 13pt，表头加粗，表头行加淡下划线当分隔线。
- 列宽按**显示宽度**算（CJK 记 2、ASCII 记 1），再按「目标宽 − 实测宽」给每格最后一个非空格字符补 kern。
- 三列表格四行的第 2/3/4 个 `|`，实测 x 偏差 **0.00 pt**；四列表格五行的 5 个 `|`，偏差也是 **0.00 pt**。
- 光标移进某一行，该行撤掉 kern、回到源码宽度；其他行不动。

## 2. 为什么不用 NSTextTable

`spike/tables` 的实测（`/tmp/tables2/metrics.txt`）给出两条结论：

1. `NSTextTable` 在 TextKit 2 下不接管排版，写进去只得到「一格一段落」。
2. 逼它生效要把 TextKit 2 退回 TextKit 1，而且必须把「一行」摊成「一格一段落」。

第 2 条等于改写正文结构。正文是唯一真相，所以这条路排除。
剩下的一条路是「等宽 + kern，只改属性」，本实现走这条。

上一版这里算错两处，都已修掉：

- 列宽按字符数算，没按显示宽度算；中文一格只有 1 个字宽，目标宽直接偏小一半。
- kern 加满整格或乘 2，pipe 被推过头。

这两处在 `TableRenderingTests` 里各有用例盯着（见第 7 节的变异验证）。

## 3. 识别规则

入口：`TableLayout.blocks(in:)`，纯函数，只读文本。

一个块要同时满足：

- 连续的 pipe 行；
- 至少 2 行：第 1 行表头，第 2 行分隔行；
- 分隔行每格匹配 `:?-+:?`（`---`、`:---`、`---:`、`:---:`）；
- 所有行列数一致；
- 每行首尾都有 `|`（前后允许空白）；
- 围栏代码块里的 pipe 不算（沿 `scanLineMarkers` 的围栏状态）。

任一条不满足，整块按普通正文显示。

输出只有区间，没有文本：`rows[].contentRange`（整行）、`rows[].pipes`（每个 `|`）、`rows[].cells`（pipe 之间）。

## 4. 宽度与 kern

```text
unit        = 等宽 13pt 下 "0" 的宽度（本机 8.04 pt）
colWidth[c] = max(displayWidth(cell)) + 2        // 单位是显示宽度，两侧各留一格
target[c]   = colWidth[c] * unit
measured    = NSAttributedString.size(withAttributes: [.font: cellFont]).width
kern        = target[c] - measured               // 只加一次，只加在该格最后一个非空格字符上
pipeX[c]    = Σ(target[i] + unit)                // i < c
```

两个实现细节都有实测依据：

- kern 加在该格最后一个**非空格**字符上。加在尾随空格上时 TextKit 的 `firstRect` 只报一半位移，验收量不准。
- 表头行用 bold 字体**实测**宽度，但目标宽仍用 regular 的 `unit`。本机两者都是 8.04 pt，换字体也不会把列宽拉歪。

## 5. 渲染属性

`TableLayout.attributes(for:in:caretParagraph:)` 返回要写的属性列表，`EditorView.applyTables` 只负责写进 `NSTextStorage`。

| 目标 | 属性 | 备注 |
| --- | --- | --- |
| 整块 | `.font` = mono 13（表头 bold）、`.paragraphStyle` = 表格段落 | 段落样式 `lineBreakMode = .byClipping`，表格行不软换行 |
| 表头行 | `.underlineStyle = .single` + `.underlineColor` 淡色 | 当表头下方的分隔线 |
| 分隔行 | `.foregroundColor` 40% alpha | 光标在该行时恢复 `labelColor` |
| 每格末字符 | `.kern` | 光标所在行不加 |
| pipe | `.foregroundColor` 次级色 | 保留可见，对齐验收要靠它 |

光标行「露源码」的判定：行的 `contentRange` 与光标所在段落有交集。
切换走 `refreshSyntaxMarksForCaret`，与列表标记同一套路径。

## 9. 已知边界

- 不支持省略首尾 `|` 的写法（GFM 允许，本实现要求首尾都有 pipe）。
- 不支持单元格内的转义 pipe `\|`：会当成列分隔符。
- 表格行不软换行（`.byClipping`）。表格宽于编辑列时右端被裁，没有横向滚动。
- 表格行里的行内代码（`` `a|b` ``）里的 pipe 仍按分隔符处理。
- 表格与前后段落之间不强制空行。
